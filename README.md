# Crop leaf disease detection (ClimaCrop)

Web app and API that classify **diseased or healthy crop leaves** from a photo and optionally suggest treatments—built by **team ClimaCrop**.

---

## About the project

Smallholder and field teams often spot leaf symptoms late. This project gives a **single place** to upload a leaf photo, get a **disease label with confidence**, see **runner-up guesses**, and read **short treatment-style guidance** when a local LLM is available.

**What it covers:** **4 crops** (Cottons, Maize, Rice, Wheat) and **26 classes** (diseases + healthy / special folders), trained on **35,000+** labeled leaf images (your full dataset stays off GitHub; only the trained weights ship in `models/`).

**How it is built:** **PyTorch** + **torchvision** for the image classifier, **OpenCV** for leaf-focused preprocessing (HSV mask + optional background blur), **FastAPI** for the backend, and a **plain HTML/CSS/JS** frontend—no React build step. **Treatment text** is generated by **[Ollama](https://ollama.com/)** on your machine (default model name `llama3.1:8b` in the API). There are **no paid cloud LLM API keys** in the repo.

---

## How users interact with the UI

1. **Start the server** (see the **Run API + web UI** section below) and open the app URL in a browser (e.g. `http://127.0.0.1:8001`).
2. **Upload a leaf image:** drag and drop onto the upload area, or click **Choose File** and pick a JPG/PNG (same limits as the site: large files may be rejected in the UI).
3. **Preview:** the chosen image appears with a remove (**×**) control if the user wants to pick another file.
4. **Analyze:** click **Analyze Disease**. The UI shows a short “Analyzing…” state while it calls `POST /api/predict` with the image.
5. **Left column — prediction:** the app shows the **predicted class name**, a **confidence** bar, and **top alternative labels** so users can see close calls between similar diseases.
6. **Right column — recommendations:** if Ollama is running, **treatment-style text** appears for the predicted disease; if Ollama is off or times out, the user still keeps the numeric prediction, and the recommendations area may show an error or placeholder message.

No account or login is required; everything runs against your own server.

## Model & pipeline

| Item | Detail |
|------|--------|
| **Classifier backbone** | **EfficientNet-B0** by default (`config.yaml` → `model.backbone`). You can switch training to **ResNet-50** in the same config; the saved checkpoint records which backbone was used. |
| **Pretraining** | ImageNet weights for the backbone, then **fine-tuned** end-to-end on your crop/disease folders (`src/train.py`). |
| **Head** | The final linear layer size matches the **26** classes in `models/class_mapping.json` (one softmax over all crops). |
| **Input size** | **224×224** RGB after preprocessing (`data.img_size` in `config.yaml`). |
| **Preprocessing (train & inference)** | Load image → **HSV leaf segmentation** (green-ish leaf range) → optional **blur outside the mask** so the network focuses on the leaf → resize/normalize like ImageNet stats (`src/preprocessing/`). |
| **Training extras** | Train/val split, augmentations (rotation, flip, brightness/contrast, light scale/shift), Adam-style optimization and early stopping as in `config.yaml`. |
| **Artifacts** | `models/best_model.pt` holds weights + metadata (`backbone`, `num_classes`, …). `models/class_mapping.json` maps string labels to class indices for inference and the API. |

The UI only sends the image to your backend; the **PyTorch model runs on the server** (GPU if available, else CPU per config).

## Verified label set (26 classes)

Labels are stored in `models/class_mapping.json` (single multi-crop head). Examples: `Cottons_Healthy`, `Maize_Common Rust`, `Rice_Leaf Blast`, `Wheat_Wheat___Yellow_Rust`, etc. Full list is in that JSON file.

## Repository layout

```text
desease_detection/
├── app.py                 # uvicorn entry (see Run API below)
├── config.yaml            # data paths, model, training hyperparameters
├── requirements.txt
├── models/
│   ├── best_model.pt      # trained weights + backbone metadata
│   └── class_mapping.json
├── sample_images/screenshots/   # UI screenshots for the README / repo
├── frontend/              # static UI (served by FastAPI)
└── src/
    ├── api.py             # FastAPI app
    ├── train.py
    ├── inference.py       # CLI + Ollama recommendations
    ├── dataset.py
    ├── preprocessing/
    └── utils/
```

**Do not commit** the raw image folders (`Cottons/`, `Maize/`, `Rice/`, `Wheat/`). They are listed in `.gitignore` so you only push code, `models/`, and samples. Keep the full dataset on your machine or release it separately (e.g. zip / cloud storage).

## Setup

```bash
cd desease_detection
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Configure training data

1. On your disk, arrange images like:

   ```text
   <your_data_root>/
   ├── Cottons/<class_folders>/…images…
   ├── Maize/<class_folders>/…
   ├── Rice/<class_folders>/…
   └── Wheat/<class_folders>/…
   ```

2. In `config.yaml`, set `data.root_dir` to that folder (absolute path is fine). Crops are already the four names above; class folders must match what you used when building `class_mapping.json`.

## Train

From the `desease_detection` directory (so `config.yaml` and `models/` resolve correctly):

```bash
python -m src.train --config config.yaml
```

Writes `models/best_model.pt` and `models/class_mapping.json`, uses train/val split and optional early stopping from `config.yaml`.

## CLI inference (one image)

```bash
python -m src.inference --config config.yaml --image_path path/to/leaf.jpg
# Skip Ollama:
python -m src.inference --config config.yaml --image_path path/to/leaf.jpg --disable_llm
```

## Run API + web UI

```bash
# from desease_detection/
python app.py
# or: uvicorn src.api:app --host 0.0.0.0 --port 8001
```

Open the shown URL in a browser. Endpoints include `GET /health`, `POST /api/predict` (multipart file), optional `POST /api/recommendations` (JSON body with `disease_name`).

**Recommendations:** install Ollama, pull a model (e.g. `ollama pull llama3.1:8b`), run `ollama serve`. Override host with `export OLLAMA_BASE_URL=http://127.0.0.1:11434` if needed. No third-party LLM API keys are used.
